## Problems found and corrected during verification

- Blind-arena reports were not completely bound to the state's exact current
  report, before/after commitments, episode history, and reconciled counters.
  Those bindings are now mandatory and replay-verified before success.
- Malformed report and checkpoint values could escape through verifier
  exceptions. Public verification/loading is now bounded, no-throw, and
  fail-closed for malformed, duplicate-key, non-finite, oversized, or
  structurally invalid input.
- The arena core originally accepted replacement explorer/cancellation callables
  and Event-like objects. It now rejects custom callbacks and requires an exact
  standard `threading.Event` for cancellation.
- Blind-arena CLI validation originally happened after generic Attestor parsing,
  key-file reads, brain/persona setup, and routing, and some unrelated options
  could be ignored. A dedicated exact allowlist now dispatches first and rejects
  positional, abbreviated, duplicate, unknown, project/key-path, model, tool,
  execution, and network arguments before unrelated initialization.
- UI verification found cancellation-lifecycle, request-body, terminal-cleanup,
  and checkpoint link/reparse boundary weaknesses. Cancellation and body limits
  now fail closed, cleanup preserves a verified terminal state, and unsafe
  reparse/non-regular checkpoint targets and parents are rejected.
- Manual HTTP replay found that the token-bound loopback start route accepted
  simultaneous `Content-Length` and `Transfer-Encoding` and invoked start. The
  server now rejects ambiguous, missing, duplicate, or invalid arena-route body
  framing, closes the connection, and a raw-socket regression proves `400` with
  no action invocation. No exploit or host escape was demonstrated.
- Profile file/byte and graph limits were initially described too broadly. The
  signed profile contract, reports, UI, and documentation now state that these
  are stage-specific coding-worker ceilings; inherited analyzers expose their
  own caps and gaps.
- The semantic graph limit was initially checked after graph construction. It
  is now enforced before each public graph row is constructed, with an explicit
  truncation gap and a defense-in-depth post-check.
- A Node-enabled UI test exposed that arbitrary JSON could borrow an
  Attestor-looking version label. UI identity now requires an Attestor schema and
  schema/version consistency.
- The UI initially used the per-worker timeout as its end-to-end process
  timeout. It now derives a distinct bounded outer-process timeout so worker
  cleanup and report verification are not cut off at the worker deadline.
- Truth Guard 3.5 and 4.0 accepted an unsigned `algorithm=none` ledger when a
  verification key was supplied. They now reject the downgrade, and focused
  adversarial tests cover both versions.
- Attestor 4.0 and Security Fabric truncated findings before global severity
  ranking, so a late critical result could be hidden by earlier lower-severity
  rows. Both now use deterministic global severity-ranked bounded selection.
- Exact-file remediation could widen to the containing project and read sibling
  files. Patch Guard now preserves exact-file scope and refuses project-copy,
  project-hash, project-scan, and test claims unless project scope is explicitly
  selected. Unsupported exact files report partial coverage rather than clean.
- Redacted object keys could collide, and excessive nesting could surface a raw
  `RecursionError`. Redaction is now collision-safe and deep input fails through
  typed bounded guard errors.
- CJP transaction cleanup initially lost partial-backup, staging, rollback-stage,
  and lock-cleanup evidence. Transaction reports now retain bounded
  `cleanup_errors`, state `cleanup_complete` truthfully, sanitize the text view,
  and return a warning exit without relabelling an already committed edit as
  failed.
- The self-scan found one unused compatibility import and an assertion-based
  production invariant. They were removed or replaced with explicit fail-closed
  checks. Its earlier cleanup observations drove the transaction fixes above;
  that pre-fix report is stale and was not accepted as final evidence.
- Truth Guard 3.5 initially passed a large compatibility document directly to
  the older 100,000-node independent validator. It now applies a separate
  500,000-node full-document boundary and a deterministic digest-bound
  exact-field projection. The complete source hash and projection metadata are
  replay-checked.
- Attestor 4.1 now treats typed inherited Truth Guard compatibility failures as an
  explicit unavailable compatibility proof rather than aborting the current
  analysis. The gap remains visible and no unavailable legacy result is called
  complete.
- Attestor 4.1.4's direct CLI initially allowed expected bounded failures to surface
  as Python tracebacks. Text now emits a bounded stderr failure; JSON and SARIF
  emit parseable failure envelopes with no result and no disclosed traceback.
- Attestor 3.0's high-cardinality semantic report exceeded the inherited Truth
  Guard node ceiling. A local hard boundary, digest-bound replayable projection,
  and locally bounded deterministic serializer now preserve finding filtering
  without raising the global legacy limit.
- The posture scanner now rejects duplicate JSON object keys through an
  explicit gap instead of silently accepting last-key-wins semantics.
- Detector regex-rule declarations and dynamic nonce assignments no longer
  masquerade as executable legacy-crypto, script, persistence, or static-nonce
  behavior.
- The final scan contains no critical finding and one high inferred framing
  heuristic at the explicit rejection helper. All 232 rows are adjudicated
  `insufficient`; the high row is not a confirmed defect, and raw-socket tests
  prove the ambiguous requests are rejected with no action invocation.

## Residual limitations

- Attestor is a defensive static-analysis toolkit, not a proof of correctness.
- Blind-arena success cannot perform or prove a VM, hypervisor,
  operating-system, container, or host escape; it proves only replay of the
  compiled synthetic state transition.
- Blind checkpoints use unkeyed SHA-256 consistency commitments, not
  authentication against a malicious writer with same-account access.
- The offline default does not establish live vulnerability or deployment
  state.
- Windows does not provide the POSIX `RLIMIT_AS` worker boundary through the
  standard library. Parent-process memory is not profile-limited.
- Network denial in Python workers is contractual, not a kernel network
  namespace.
- The strongest profile can be slow and memory-intensive on very large source
  trees. Use South Park by default, and treat process/output boundary failures
  as incomplete coverage rather than a clean result.
- Generated improvements remain review candidates until separately authorized
  scanner, build, and test gates pass. Automatic apply is disabled.
